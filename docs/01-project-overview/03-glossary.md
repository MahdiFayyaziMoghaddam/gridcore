# GridCore - Glossary of Terms

## 📚 Definitions

### A

**Active Session**
: A session that is currently running and has at least one user (owner or temp owner) connected. Active sessions are stored in the WebSocket server's memory.

**Authentication**
: The process of verifying a user's identity. GridCore uses NextAuth.js with email/password, GitHub, and Google OAuth.

### B

**Binary Files**
: Files that are not text-based (e.g., images, videos, executables). GridCore does not support binary files.

**Blob Storage**
: Cloud storage service for binary data. GridCore uses Vercel Blob Storage to store saved session ZIP files.

**Broadcast**
: The act of sending a message from the server to all connected clients in a session. Used for diffs, cursor positions, chat messages, and file operations.

### C

**Client**
: The user's browser running the GridCore application. All file state and processing happens on the client.

**Client-Centric Architecture**
: An architecture where the client maintains the source of truth and the server only facilitates communication between clients.

**Codebase**
: The entire collection of files and folders in a session. Includes file contents, file tree structure, and metadata.

**Collaboration**
: The act of multiple users working together on the same codebase in real-time.

**CRDT (Conflict-free Replicated Data Type)**
: A data structure that enables real-time collaboration without conflicts. GridCore uses `yjs` as the CRDT implementation.

**Cursor Tracking**
: The feature that shows other users' cursor positions in the editor in real-time.

### D

**Database**
: PostgreSQL database managed with Drizzle ORM. Stores user accounts, session metadata, and saved session references.

**Diff**
: A set of changes to a file (insertions, deletions, modifications). Generated by yjs and broadcasted to all users.

**Drizzle**
: TypeScript ORM for PostgreSQL used by GridCore for type-safe database operations.

### E

**Export**
: The process of downloading the entire codebase as a ZIP file from the session. Only owners can export.

**Editor**
: The Monaco Editor component where users write and edit code.

### F

**Fallback Name**
: A default session name generated when the owner doesn't provide one. Format: `"new-session-<random-things>"` (not the ID).

**File Explorer**
: The sidebar component that displays the file tree of the current session.

**File Tree**
: A hierarchical representation of files and folders in the codebase.

**File Operations**
: Creating, deleting, and renaming files and folders.

### G

**Git**
: Version control system. GridCore does not have direct Git integration but supports import/export of codebases via ZIP files.

**Glob**
: A pattern matching mechanism used for file filtering. Not currently used in GridCore.

**Grace Period**
: A time window for reconnection after disconnection. GridCore does not use grace periods; users are removed instantly.

### I

**Import**
: The process of uploading a ZIP file to start a session with an existing codebase.

**In-Memory Storage**
: Temporary data stored in the WebSocket server's memory. Lost on server restart. Used for active sessions, user connections, rate limiting, and chat cooldowns.

**Invite Link**
: A URL containing the session ID that users can share to invite others. Example: `https://gridcore.vercel.app/join/123e4567-e89b-12d3-a456-426614174000`.

### J

**Join**
: The process of a user entering an existing session using the session ID.

### L

**Last-Write-Wins**
: A conflict resolution strategy where the last edit to a file line is the one that persists. GridCore uses this for conflicting edits on the same line.

### M

**Main Owner**
: The user who created the session. Has full control including saving, exporting, changing the session ID, and granting/revoking temp ownership.

**Minimap**
: A small overview of the entire file displayed in the scrollbar area of Monaco Editor.

**Monaco Editor**
: The code editor used in GridCore (the same editor powering VS Code).

**Multiple Tabs**
: A user opening the GridCore application in more than one browser tab simultaneously. This is blocked.

### N

**NextAuth.js**
: The authentication library used by GridCore to manage login, sessions, and OAuth providers.

**Next.js**
: The React framework used to build GridCore. Uses the App Router.

**Notification**
: A toast notification displayed to users when someone joins or leaves a session. Uses `react-toastify`.

### O

**OAuth**
: Open standard for access delegation. GridCore supports GitHub and Google OAuth providers.

**Owner**
: The main owner or temp owner of a session. Has elevated privileges.

### P

**Pair Programming**
: A collaborative practice where two developers work on the same codebase simultaneously.

**Persona**
: A fictional user profile used to guide design and feature decisions.

**PostgreSQL**
: The relational database used by GridCore.

**Presence**
: The feature showing which users are online and what they're currently doing.

**Private Session**
: A session that requires a session ID to join. All sessions are private by default.

### R

**Rate Limiting**
: The process of limiting the number of requests a user can make in a given time window. Used to prevent abuse.

**Reconnection**
: The process of a user reconnecting to a session after a disconnect. GridCore requires manual reconnection by the user.

**Regular User**
: A user in a session who is neither the main owner nor a temp owner. Can only edit files, view, and chat.

**Responsive Design**
: Design that adapts to different screen sizes. GridCore is desktop-first but works on tablets.

### S

**Saved Session**
: A session that has been saved to the database and storage. Saved sessions persist and can be loaded later.

**Server**
: The backend application running on Vercel. Handles authentication, WebSocket connections, database operations, and storage.

**Session**
: A collaborative coding session with a unique ID. Contains a codebase and multiple users.

**Session ID**
: A unique identifier for a session. Format: UUID v4 (e.g., `123e4567-e89b-12d3-a456-426614174000`).

**Session Name**
: An optional name for the session set by the owner. Other users can see the session name.

**Sidebar**
: The left panel in the GridCore UI containing tabs for Files, Chat, and Users.

**Sticky Sessions**
: A load-balancing strategy where a user is always routed to the same server instance. Not currently used in GridCore.

**Storage**
: Vercel Blob Storage used to store saved session ZIP files.

**Syntax Highlighting**
: The feature that colors code based on the programming language.

### T

**Temp Owner (Temporary Owner)**
: A user granted temporary ownership of a session by the main owner. Can create/delete files and keep the session alive if the main owner disconnects.

**Toast Notification**
: A small popup notification used for join/leave events and other system messages.

### U

**UUID (Universally Unique Identifier)**
: A 36-character unique identifier. Used for session IDs in GridCore.

**Unsaved Session**
: A session that has not been saved to the database. Unsaved sessions exist only in memory and are lost on server restart or owner disconnect.

**User**
: A registered user with an account in the GridCore system.

**User Presence**
: The feature showing which users are online, what file they're editing, and their current status.

### V

**Vercel**
: The cloud platform used to deploy GridCore. Provides hosting, WebSocket support, and Blob Storage.

**Vercel Blob Storage**
: Cloud storage service used to store saved session ZIP files.

**Vercel Edge Runtime**
: The runtime environment used for the WebSocket server in GridCore.

**VSCode**
: Visual Studio Code. GridCore's UI and editor are inspired by VSCode.

### W

**WebSocket**
: A protocol for real-time, bidirectional communication between clients and server. Used for all real-time features in GridCore.

**Word-Based Suggestions**
: Auto-completion suggestions based on words already present in the file. No language server or semantic analysis.

### Y

**yjs**
: A CRDT library used for real-time collaboration. Handles diffs, conflict resolution, and state synchronization in GridCore.

### Z

**ZIP**
: A compressed file format. Used for importing, exporting, and saving codebases in GridCore.

**Zustand**
: A state management library used in GridCore for client-side state.
